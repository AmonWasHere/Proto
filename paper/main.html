Trustworthy but Silent:
Measuring LLM Security Verdicts with the Four-Way Decomposition
Author NameIndependent Researcher — author@example.org

Abstract

Large language models (LLMs) are increasingly used as verifiers of security findings: a scanner proposes a candidate, and a model adjudicates whether it is real. Whether such a verdict can be trusted is rarely measured. We adapt the four-way decomposition — an instrument previously used to show that static analyzers flag constructs rather than vulnerabilities — to LLM verifiers, and add evidence gating, an adversarial comment attack, a composition study, and a calibration analysis. Across five model families and a real-fix corpus we find that (i) an evidence-grounded LLM tracks the fix markedly more often than a pattern matcher (19–24% vs. 4.8%, no over-reporting), but (ii) it abstains on about half of all judgements and misses most genuine fixes, so its bottleneck is coverage, not accuracy; (iii) almost every successful adversarial evasion is an abstention rather than a false positive, and an adaptive attacker reaches 50% evasion where fixed templates reach 26%; and (iv) composing an LLM with a weaker deterministic verifier relocates trust — grounding a claim helps for free, while requiring consensus with a weaker tool loses recall for no gain. Our evidence is directional (a 21-pair security subset and 5-pair cross-family sets), and we state this plainly. We release a reproducible harness and argue that abstention should be measured and reported as a first-class failure mode of security agents.

Index Terms—security verification, large language models, empirical measurement, abstention, adversarial robustness, static analysis, calibration.

I. Introduction

Automated vulnerability analysis has converged on a standard shape: a policy queries tools and a code graph, and is trained or prompted to report findings [1], [2], [4], [6]. As models take on the verification role — deciding whether a candidate is real — the question becomes whether their verdicts can be trusted. Prior work shows that LLM security detectors are highly susceptible to adversarial source comments [5]; what has not been measured systematically is whether an LLM verdict tracks the vulnerability, how it fails when it does not, and how it behaves under composition and an adversary.

A separate line of work established that benchmark scores do not predict real detection: for a static analyzer, the fraction of commits whose verdict moves with a fix can be two orders of magnitude below its benchmark true-positive rate, and the four-way decomposition — whether a tool flagged both revisions, the vulnerable revision only, the fixed revision only, or neither — made that visible [15]. We apply that instrument to LLM verifiers and extend it with evidence gating, an adversarial comment attack, a composition study, and calibration.

Contributions.

  • An instrument. We apply the four-way decomposition to LLM verifiers, gate every verdict on machine-checkable evidence, and make coverage (languages checked vs. unchecked) explicit. The harness is released.
  • A coverage-bound finding. An evidence-grounded LLM verifier tracks the fix far more often than a pattern matcher (19–24% vs. 4.8%) and does not over-report (1.0–1.25× vs. 6.0×), but abstains on ~50% of judgements and misses most genuine fixes: its bottleneck is silence, not error.
  • Abstention as the attack surface. Under adversarial comments, almost every successful evasion is an abstention rather than a false positive; an adaptive attacker reaches 50% evasion against 26% for fixed templates.
  • Composition relocates trust. Evidence grounding removes an ungrounded positive at no recall cost; requiring agreement with a weaker deterministic verifier loses recall and gains nothing.
  • Calibration and cost. The verifier is well calibrated (ECE 0.025) and precise (0% fixed-side false positives) when it commits; disabling model thinking cuts cost ~8× at a measured precision cost, and a content-addressed verdict cache removes 100% of repeat cost.

We are explicit that our evidence is directional and small (Section VII); we treat it as a measurement-methodology contribution, not a claim of a large effect.

II. Related Work

LLM agents for vulnerability analysis. OpenAnt [4], FuzzingBrain V2 [7], DREA [8], CLEAR [9], and ATLANTIS [10] combine LLMs with static analysis, symbolic execution, and fuzzing. They report improved discovery; they generally do not measure whether a verdict tracks the vulnerability.

RL from verifiable rewards. VulAgentRL [1] uses a code property graph as both a tool and a reward verifier with exact node matching; Antares [2] trains small models with verifiable rewards; EAVA [3] couples supervised tuning with reinforcement learning. We do not train; we ask what trust such a grounded verdict earns at inference time.

Adversarial input. ALIBI [5] shows adversarial source comments defeat LLM detectors with >90% success; CoER [11] co-evolves attacker and defender for indirect prompt injection. We attack the verifier rather than the detector, split evasion by outcome, and include an adaptive attacker.

Abstention and calibration. AWA-RL [12] learns to abstain rather than fabricate in open-domain QA. We bring abstention into security verification and show it is the dominant adversarial target.

Benchmarks and validity. The OWASP Benchmark [13] is the standard scanner yardstick; JavaVFC [14] is a corpus of vulnerability-fixing commits. A companion study [15] showed the OWASP score is not well defined and does not predict real detection, and introduced the four-way decomposition; a 2026 survey [16] identifies weak oracles, temporal leakage, and unreported budgets as recurring validity threats. Our work extends [15] from static tools to LLM verifiers.

III. Method

A. Four-way decomposition

For a vulnerable/fixed revision pair, we classify a verifier's verdict into one of four cells: both (flagged before and after the fix — not detection), vuln-only (flagged only before — a flip, i.e. detection), fixed-only (noise), and neither (a miss). We report the flip rate, the naive coverage, and their ratio, the over-report factor.

B. Verifier arms

V1 (LLM, ungated): the verdict is taken as-is. V1g (LLM, gated): every cited evidence reference must resolve to a real syntax node, or a positive verdict is downgraded to unknown. V2 (tool): the pinned analyzer's verdict. V5 (hybrid): flagged only if the gated LLM and the tool agree.

C. Bounded verdict request and evidence gating

The model never sees a repository. For a candidate it receives the candidate (rule, location, CWE hint), the enclosing function extracted from a tree-sitter code property graph, and optional retrieval. It must respond with strict JSON, cite path:line references, and may answer unknown_risk. Each reference is resolved against the graph; an unverifiable positive is downgraded.

D. Adversary

Templates: five comment strategies (authority, sanitizer, tool-output, test-passed, reviewed) inserted just above the suspected sink. Adaptive: an attacker model writes a comment, observes the verifier's verdict, and refines over up to three rounds [5]. We split evasion into false-positive and abstention outcomes.

E. Calibration and cost

Per revision judgement we record confidence, correctness, and disposition; we compute expected calibration error (ECE), reliability bins, a selective-risk/coverage curve, false-negative rate on vulnerable revisions, and false-positive rate on fixed revisions. Cost is reported in tokens and, at known prices, dollars per true positive.

F. Whole-codebase view

Files are mapped to a language registry with an explicit coverage label (covered/find_only/ground_only/unsupported), and a lightweight system graph connects functions, HTTP routes, configuration sources, and dependencies to produce entry-to-sink path candidates whose coverage is that of their least-covered hop.

IV. Experimental Setup

Corpora. (i) 21 Java security-fix pairs from JavaVFC [14] (784 commits; 327 usable single-file; 207 materialised offline; the strong-security subset used here is 21). (ii) 5 hand-built Python vulnerable/fixed pairs and 3 canaries. (iii) The prior study's 21-file Java control set (18 vulnerable, 3 safe). Each revision is an isolated file; the commit message is supplied as candidate context.

Analyzers. opengrep 1.30.0 with the prior study's pinned 690-rule Java ruleset (sha256 77df32e0…) and a minimal 5-rule Python ruleset.

Models. Five families via an OpenAI-compatible API: gpt-oss-120b, gpt-oss-20b, qwen3.8-27b, deepseek-flash, deepseek-v4-pro. The scaled JavaVFC run uses deepseek-flash; cross-family checks use the 5-pair Python set.

Reproducibility. All assets are pinned by hash; the control reproduction and the Python-pair measurement run fully offline; 112 tests accompany the harness.

E. Cost

Output tokens dominate (~91% of cost). Disabling model thinking reduced output from 121,596 to 5,271 tokens over 42 judgements (~8× lower cost) but introduced fixed-side false positives (0%→9.5%) and worsened ECE (0.153→0.207). A content-addressed verdict cache keyed on the model, prompts, and slice removed 100% of repeat cost. At off-peak prices the gated verifier costs ≈$0.0017 per judgement.

VI. Discussion

The bottleneck is silence. The verifier is calibrated and never false-positives on the fixed side, yet abstains on half of all judgements and misses most fixes. Optimising for precision alone would miss this. We argue abstention should be reported as a first-class outcome alongside precision and recall.

Attacks target abstention. Because the verifier already abstains when evidence is thin, an adversary does not need to convince it a vulnerability is safe — only to make it unsure. Defences that only suppress false positives leave the dominant path open.

Composition relocates trust. Grounding a claim in verifiable evidence is cheap and strictly helpful here. Requiring consensus with a weaker verifier inherits that verifier's blind spots. “Add another verifier” is not a reliability strategy; “make the existing verdict answer for itself” is.

A practical pitfall. A reasoning-model verifier silently degrades to “always abstain” when the token budget is consumed by reasoning tokens (finish_reason=length, empty content). Without the decomposition this is indistinguishable from a null result.

VII. Threats to Validity

Scale. The scaled result is 21 security pairs; cross-family claims are on 5 pairs. Numbers are directional, not precise; we do not report confidence intervals for the small-sample comparisons. Labels. JavaVFC is a screening corpus; a companion audit [15] found only ~18% of it is a genuine security fix, so recall is a floor. Input shape. Each revision is an isolated file — a floor for tools that resolve types. Non-determinism. Reasoning models vary at temperature 0; we observed 38.1% and 28.6% detection for the same configuration. Single family at scale. Only deepseek-flash was run on the scaled corpus. Contamination. Public fixes may appear in pretraining data; a temporal or private holdout is not yet used. Adversary. Templates are fixed; one adaptive attacker was used with shallow adaptivity.

VIII. Ethics and Responsible Release

The adversarial comment generator is dual-use. This work is defensive: its purpose is to measure and expose a failure mode so that verifiers can be made robust. We do not release a turnkey attack service; the generator is a small, reproducible component of a measurement harness, and the paper reports defences (evidence gating, coverage reporting, abstention accounting) alongside the risk.

IX. Reproducibility

The harness, pinned analyzers and rule sets, control set, and corpora are released. The control reproduction (12/18 vulnerable, 1/3 safe) and the Python-pair measurement run fully offline; 112 tests accompany the code. A verdict cache makes repeat runs deterministic and free.

X. Conclusion and Future Work

LLM security verifiers track fixes far better than pattern matchers, are calibrated and precise when they commit, and are nonetheless silent on about half of their inputs — a weakness that adversarial comments amplify, and that composition with deterministic tools does not fix. Future work must (i) scale to hundreds of genuine fixes across at least two languages and three model families with confidence intervals, (ii) evaluate path-level candidates on multi-file revisions, and (iii) treat abstention and coverage as first-class metrics for security agents.
